## Durable cross-cutting separations

CKR-C explicitly conserves:

- Monitoring Scope ≠ ecosystem existence ≠ Capability Authorization ≠ Assertion Authority;
- Entity Identity ≠ name ≠ replacement/succession;
- Semantic Definition ≠ realized state ≠ normative Expectation;
- Responsibility Assignment ≠ Assertion Authority ≠ Capability Authorization;
- Classification ≠ Policy Context ≠ compliance/authorization/Impact;
- Expectation ≠ Baseline;
- Observation ≠ Assessment; missing evidence ≠ observed absence;
- typical ≠ healthy; atypical ≠ degraded;
- Change Intent ≠ Deployment ≠ Change;
- execution success ≠ output existence ≠ freshness ≠ data health;
- planned topology ≠ active Lineage; Lineage/reachability ≠ exposure ≠ Impact ≠ cause;
- Investigation lead/localization/closure ≠ causal status/confirmation;
- Impact candidate ≠ encounter/exposure ≠ effect ≠ consequence ≠ causal attribution;
- Annotation ≠ structured operational truth;
- Explanation ≠ independent truth source;
- Gate readiness ≠ decision ≠ delivery ≠ enforcement ≠ execution;
- Execution Gate ≠ Propagation Safeguard;
- Safeguard proposal ≠ authorization ≠ request ≠ enforcement ≠ prevention ≠ release ≠ recovery;
- Capability Authorization ≠ Assertion Authority ≠ evidence sufficiency ≠ enforcement;
- event/effective time ≠ knowledge/record time; current retrospective state ≠ as-known-at-cut state ≠ retained communication.

CKR-C may cite later stable IDs when they materially constrain a concept boundary but does not take ownership of REF/AUTH/HLTH/OPS/EXPL/INTG/ARCH families.

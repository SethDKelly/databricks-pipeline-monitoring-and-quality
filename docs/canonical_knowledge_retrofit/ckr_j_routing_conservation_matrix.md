# CKR-J Routing Conservation Matrix

**Status:** ACCEPTED — CKR-J COMPLETE

## Purpose

CKR-J changes discovery, stable-reference resolution and drift enforcement only. It makes canonical ownership cheaper and deterministic to reach without creating another semantic authority, rewriting accepted contract meaning, undoing CKR-I progressive disclosure, or making design history undiscoverable.

## Conservation rules

| Surface | Before CKR-J | Accepted CKR-J result | Must not become |
|---|---|---|---|
| OKF | routing projection with residual pre-CKR-I ownership text | canonical-first current-truth routing; history explicitly provenance | semantic authority or contract copy |
| Stable ID | exact occurrence search + manual authority resolution | exact ID → one inventoried canonical stable definition → `owner_path::ID` | first-match search, line identity, duplicated semantic registry |
| ARCH stable definitions | compact segment owners with indexes/lists | compact forms retained as canonical addressability | 500 duplicated headings or restored one-file-per-ID tree |
| Historical search | mixed into occurrence results | explicit `--history` secondary discovery | current-owner selection |
| Agent routing | manual exact-hit resolution | canonical exact-ID resolver or one bounded OKF route | full-corpus preload or tool-specific semantic forks |
| Knowledge maintenance | direct resource impact only | `RESOURCE` + canonical `BODY-LINK` review candidates | automatic semantic edits |
| CI | structural routing checks | exact canonical coverage + route-state enforcement + adversarial guards | domain/production health claim |
| Phase 001–010 | design history/provenance | remains discoverable for rationale/history | alternate current owner |

## Stable-reference invariants

1. Accepted ranges remain SYN-001–035, REF-001–030, AUTH-001–053, HLTH-001–066, OPS-001–123, EXPL-001–160, INTG-001–270 and ARCH-001–500.
2. Accepted total remains **1,237**.
3. Every accepted ID has exactly one canonical stable definition inside inventoried family target documents.
4. Definition forms remain **737 headings + 416 ARCH Stable ID index members + 84 ARCH stable-contract list members**.
5. Default resolution returns the canonical owner only; historical occurrences are opt-in and never compete with it.
6. Stable locator is `owner_path::ID`; line numbers, renderer slugs, search rank, recency and Git history are not identity.
7. Routing machinery contains no contract prose and cannot reinterpret meaning.
8. Missing/duplicate canonical definitions fail routing instead of falling back to history or memory.
9. CKR-J does not manufacture per-ID ARCH prose where CKR-I intentionally conserved segment-level architecture.

## OKF invariants

1. OKF remains v0.2 routing/catalog projection only.
2. Stable semantic domain resources are canonical-first.
3. Design-history links may serve explicit provenance/history only.
4. Seven domain routes remain compact; no one-entry-per-ID expansion.
5. Broken/moved canonical links fail routing validation without erasing underlying semantics.

## Agent-routing invariants

1. Human-selected task remains scope anchor.
2. Current canonical owner outranks OKF, search order, phase chronology, vendor guidance and memory.
3. Known IDs may bypass OKF; unknown semantic location may use one bounded OKF route.
4. History is loaded only for a concrete provenance/rationale/change question.
5. Agents do not preload the full stable-ID corpus or OKF bundle.
6. Traceability keeps contract locator and implementation evidence separate.

## Drift-enforcement invariants

1. All eight stable families remain `canonicalized`.
2. Coverage remains **1,237/1,237 = 737 + 416 + 84**.
3. Stable OKF domains cannot regress to Phase 003–010 current-owner language.
4. Routing manifest cannot create semantic authority or a new stable family/range.
5. Agent routing surfaces retain the canonical resolver and ownership boundaries.
6. Historical discovery stays separate from default resolution.
7. Canonical path moves must update routing coherently or fail validation.
8. Conformance failure never authorizes semantic repair.

## Non-goals

CKR-J adds no knowledge server, vector/graph database, MCP server, new stable IDs, new ARCH semantic sections, product code or provider-specific semantic memory. CKR-K owns whole-retrofit consolidation and exit acceptance.

# Phase 009 Group 06 Decisions — Investigation, Causality & Control Sources

### D-1119 — Investigation source assembly preserves source ownership
**Status:** Accepted
Cross-source assembly does not create causal truth.

### D-1120 — Investigation triggers are not presumed causes
**Status:** Accepted
Alerts/incidents/results open bounded inquiry only.

### D-1121 — First observed is source/coverage bound
**Status:** Accepted
Earliest retained observation is not earliest real-world deviation.

### D-1122 — Earliest evidenced change remains localization
**Status:** Accepted
Temporal precedence does not create cause.

### D-1123 — Reconciliation boundary is not causal mechanism
**Status:** Accepted
Mismatch localization remains distinct from why it occurred.

### D-1124 — Consumer-effect localization is independent of causal attribution
**Status:** Accepted
Group 05 effect evidence can localize without confirming cause.

### D-1125 — Leads retain generation provenance and limitations
**Status:** Accepted
No hidden hypothesis score/rank is accepted.

### D-1126 — Lead exclusion requires bounded negative evidence
**Status:** Accepted
Missing support is not rejection.

### D-1127 — Human review/approval is Annotation unless separately authoritative
**Status:** Accepted
Title, seniority or approval does not create truth.

### D-1128 — Automated/vendor RCA output has evidence parity with human leads
**Status:** Accepted
Model origin does not self-authorize status.

### D-1129 — Causal proposition identity must be explicit
**Status:** Accepted
Cause/effect/role/scope/mechanism/time are bound before evaluation.

### D-1130 — Causal basis roles are claim-relative
**Status:** Accepted
Evidence can support, contradict or limit one proposition without globally ranking sources.

### D-1131 — No evaluated vendor automatically confirms Causal Claims
**Status:** Accepted
`confirmed` remains REF-017 + AUTH-034 gated.

### D-1132 — Remediation/rollback contrast is evidence, not automatic confirmation
**Status:** Accepted
Intervention success can support a claim while confounders remain material.

### D-1133 — Temporal/mechanism discrimination needs sufficient identity and coverage
**Status:** Accepted
Timing alone neither proves nor rejects cause.

### D-1134 — Investigation/Causal historical replay is non-rewriting
**Status:** Accepted
Late evidence may alter current retrospective status without rewriting earlier knowledge.

### D-1135 — Databricks audit is a control-action source
**Status:** Accepted
Audit actor/action/params/response/event facts retain exact source semantics.

### D-1136 — Audit request success is not universal effective enforcement
**Status:** Accepted
Asynchronous or distributed actions require later state evidence.

### D-1137 — UC grant/revoke is privilege-plane evidence only
**Status:** Accepted
It does not establish protection on every alternate path.

### D-1138 — Current UC privilege state is not historical enforcement
**Status:** Accepted
Historical claims require retained audit/state evidence.

### D-1139 — Immuta policy/config events remain separate from query enforcement
**Status:** Accepted
Configured policy does not prove application to a specific query.

### D-1140 — Immuta query audit can be strong bounded enforcement evidence
**Status:** Accepted
Applied policy/entitlement context is accepted when integration/population coverage is verified.

### D-1141 — Immuta denial is path-specific
**Status:** Accepted
One denied query does not establish global prevented exposure.

### D-1142 — Immuta coverage/registration/audit gaps remain explicit
**Status:** Accepted
Missing Immuta audit is not allow/deny evidence.

### D-1143 — Safeguard proposal, authorization and request remain separate
**Status:** Accepted
None proves effective protection.

### D-1144 — Effective Safeguard enforcement needs protected-scope evidence
**Status:** Accepted
Configuration or API success alone is insufficient.

### D-1145 — Safeguard evidence binds exact state/path/cohort/interval
**Status:** Accepted
Asset-wide labels cannot overgeneralize path coverage.

### D-1146 — Partial Safeguard enforcement is first-class
**Status:** Accepted
No global protection percentage is accepted.

### D-1147 — No encounter opportunity means no prevention credit
**Status:** Accepted
A valid enforced Safeguard can still have no REF-028 prevented-exposure result.

### D-1148 — Prevented exposure composes Group 05 + enforcement + alternate-path coverage
**Status:** Accepted
`active` + `not exposed` is insufficient.

### D-1149 — Safeguard release/regrant is not recovery
**Status:** Accepted
Post-release health/currentness/encounter is independently evidenced.

### D-1150 — Safe stale/non-delivery outcomes remain health/Impact facts
**Status:** Accepted
No universal Safeguard success score is created.

### D-1151 — Overlapping Safeguards have no hidden protector precedence
**Status:** Accepted
First configured/activated control is not automatically causal/material.

### D-1152 — Databricks Jobs cancellation is post-start interruption
**Status:** Accepted
Asynchronous cancel is not pre-start Gate HOLD.

### D-1153 — No universal native output-hold/quarantine capability is assumed
**Status:** Accepted
Path-specific Safeguard realization remains a Phase 010 architecture problem.

### D-1154 — GitHub environment protection is strong pre-start Gate evidence for the Actions job
**Status:** Accepted
Protection rules must pass before the protected job proceeds.

### D-1155 — GitHub reviewer approval, rejection, bypass and wait are distinct actions
**Status:** Accepted
They retain their documented GitHub semantics rather than collapsing into readiness.

### D-1156 — GitHub custom protection rules can externalize Gate decisions
**Status:** Accepted
The app decision does not inherit truth authority from the external source it consults.

### D-1157 — GitHub Gate evidence does not automatically gate Databricks
**Status:** Accepted
Cross-system Gate relevance requires Group 03 correlation.

### D-1158 — Databricks `Run if` / `If/else` are conditional-control candidates
**Status:** Accepted
They become DMTZ Gate realizations only under explicit criterion/opportunity mapping.

### D-1159 — Gate criterion/profile identity is explicit
**Status:** Accepted
Names such as `quality_gate` do not define criterion logic.

### D-1160 — Gate decision/delivery/acceptance/enforcement stages remain separable
**Status:** Accepted
Implementations may expose only a subset; missing stages remain unknown.

### D-1161 — Start during unsuperseded HOLD contradicts full enforcement
**Status:** Accepted
Actual Execution History can challenge control telemetry.

### D-1162 — No start alone does not prove HOLD enforcement
**Status:** Accepted
Opportunity and control/execution coverage are required.

### D-1163 — ADMIT does not imply execution
**Status:** Accepted
It establishes barrier removal/permissiveness only when evidenced.

### D-1164 — Override preserves readiness truth
**Status:** Accepted
Exceptional admission does not rewrite prerequisite state.

### D-1165 — Fallback configured, triggered, selected and enforced are distinct
**Status:** Accepted
No fallback result is inferred from configuration alone.

### D-1166 — Timeout and escalation are not Gate decisions
**Status:** Accepted
They remain triggers/workflow facts until an admission action occurs.

### D-1167 — Multiple Gates have no universal precedence
**Status:** Accepted
Explicit composition semantics are required.

### D-1168 — Gate and Safeguard remain independent controls
**Status:** Accepted
ADMIT does not release a Safeguard and Safeguard release does not ADMIT a Gate.

### D-1169 — Missing/conflicting control telemetry never proves fail-open/fail-closed
**Status:** Accepted
Integration failure remains separate from control truth.

### D-1170 — Historical control replay is source-set/retention bound
**Status:** Accepted
Audit, GitHub, Immuta and custom-control histories have different windows/detail.

### D-1171 — Control effect beyond narrow enforcement/prevention requires Causal Claim
**Status:** Accepted
Delay, staleness, harm or broader prevention attribution remains REF-013–REF-020 work.

### D-1172 — INTG-154–INTG-200 and ICE06-01–ICE06-72 are accepted
**Status:** Accepted — Phase 009 Group 06
Group 06 is complete; Group 07 is next.

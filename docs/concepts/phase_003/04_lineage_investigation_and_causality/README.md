# Group 04 — Lineage, Investigation & Causal Reasoning

**Status:** Next review group

## Goal

Define how bounded Investigations use historical typed Lineage and runtime/change evidence to discover candidates and evolve competing Causal Claims without forced root cause, while preserving analyst-driven research and safeguard context.

## Accepted handoff from Group 03

- Material, violated, atypical, or unresolved Assessments can be investigated manually where authorized.
- Automatic Investigation initiation requires explicit accepted response criteria; Group 04 does not invent alert severity policy.
- Execution duration/dependency latency, missing-output evidence, safeguards, and safeguard-induced delays are eligible investigation evidence.
- An active Propagation Safeguard is not proof that the protected data was defective or that a cause is known.

## Planned synchronization questions

- Assessment/Change/question/realization mismatch → bounded Investigation scope;
- Investigation scope/time → historical Lineage/evidence candidate discovery;
- Change Intent, Deployment, Execution History, operational timing, Observation, Assessment, Change, Safeguard, Lineage → Causal Claim evidence links;
- temporal ordering, counterevidence, alternate explanations, and causal exclusion;
- multiple contributors and unresolved closure;
- analyst-added evidence/Annotation without truth mutation;
- scope/authorization boundaries during upstream traversal;
- how prospective blast-radius context differs from retrospective causal reasoning.

# OPS-033 — Prospective Review Ownership & Group 04 Handoff

**Status:** Accepted — Phase 007 Group 03

## Purpose

Close Group 03 without creating a `Prospective Review`/`Risk` truth owner and define what later runtime reasoning may consume.

## Ownership

- **Change Intent** owns planned modification and planned topology delta.
- **Lineage** owns effective relationship/topology truth.
- **Impact** owns candidate/reachability state, including prospective candidate basis; it does not own predicted exposure.
- **Semantic Definition / Expectation / Baseline / Observation / Assessment** retain their accepted health/meaning truth.
- **Assessment** can express proposal-bound structural/compatibility conclusions where Phase 006 permits.
- **Assertion Authority / Capability Authorization / Policy Context** govern standing, permission and applicable obligations.
- **Execution Gate / Propagation Safeguard** own actual control state only when separately configured/operated.

The prospective scenario topology and change-aware review profile are derived synchronization views over these truths, not new concepts.

## Group 04 handoff

Group 04 receives:

- exact intent/proposed-state components and rollout slices;
- effective/planned topology distinctions and candidate paths;
- proposal-bound compatibility/review findings with their evaluation cut;
- explicit unresolved/restricted/conflicting candidate coverage.

Group 04 must reconstruct actual executions, active implementation versions and input/output version use from runtime evidence. It must not use prospective candidate paths, proposed versions, planned schedules, compatibility results or review assumptions as proof of what actually ran or was consumed.

## Invariants

- prospective profile ≠ runtime history;
- proposed version ≠ executed version;
- prospective candidate ≠ exposed consumer;
- compatibility review ≠ actual run success/failure;
- review obligation/approval ≠ deployment enforcement;
- no new concept is required for Group 03.

# Phase 008 Group 06 — Audience, Authorization, Safe Abstraction & Basis Inspection

**Status:** Next — not started

## Goal

Refine audience/purpose-specific authorized projection, safe abstraction, redaction/omission, cross-audience consistency and basis inspection so useful Explanation does not leak restricted source state or strengthen hidden evidence through prose.

## Accepted input

Consumes **EXPL-001–EXPL-100**. Group 05 supplies proposition-faithful internal wording/status for supported/established, unknown/unresolved, unavailable, insufficient/indeterminate, conflicting, restricted, stale, non-comparable, not-applicable, not-evidenced and evidence-backed negative states.

## Primary questions

- Which material conclusions, context, limitations and basis details may each audience/purpose receive?
- How can exact identities/values/paths/policy text be safely abstracted while preserving the same underlying proposition and epistemic strength?
- When can a coarse conclusion be visible while detailed basis is restricted?
- How should `inspectBasis` behave over mixed authorization without exposing hidden evidence through inference?
- How do different authorized projections remain consistent without requiring identical detail?

## Boundary

Authorization and redaction may reduce visible detail but may not change internal source truth, create permission, remove a material limitation, convert restricted to absent, or strengthen unknown/insufficient/conflicting states.

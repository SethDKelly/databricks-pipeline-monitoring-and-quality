# Phase 008 Group 06 — Audience, Authorization, Safe Abstraction & Basis Inspection

**Status:** Review complete — accepted

## Goal

Refine how an internally valid Explanation becomes an audience/purpose/delivery-specific authorized projection, including safe abstraction, omission/redaction, mixed basis visibility, `inspectBasis`, cross-audience consistency and inference-leakage boundaries.

## Group result

Group 06 accepts **EXPL-101–EXPL-120** and **AUD06-01–AUD06-44**.

No new concept is required. **Capability Authorization + AUTH-044–AUTH-053 own permission/disclosure truth; Explanation owns composed communication; source concepts retain substantive truth.**

The accepted projection chain is:

**internally valid material statement + complete internal basis → requester/target-audience/purpose/delivery binding → conclusion/context/limitation/basis/detail authorization → semantically valid abstraction/minimization → mosaic/inference-leakage review → visible statement/basis projection → optional high-consequence communication release → retained Explanation/audit context**.

No stage creates permission or stronger truth.

## Accepted contracts

- **EXPL-101–EXPL-104** — projection/requester/target-audience and result/basis/detail visibility binding.
- **EXPL-105–EXPL-112** — safe abstraction, epistemic monotonicity, identity/value/path/domain abstraction, material limitations and opaque-existence discipline.
- **EXPL-113–EXPL-116** — mixed-authorization derivation, `inspectBasis`, retained internal traceability and mosaic/repeated-query risk.
- **EXPL-117–EXPL-119** — cross-audience consistency, high-consequence communication release and historical/current authorization separation.
- **EXPL-120** — Group 07 handoff.

## Durable rules

- audience/purpose/delivery context ≠ permission;
- requester visibility ≠ permission to disclose to another target audience;
- private inspection ≠ export/forward/publish/client disclosure;
- conclusion visibility ≠ context/basis/provenance/detail visibility;
- visible conclusion does not require visible raw evidence, but internal traceability remains complete;
- safe abstraction may reduce detail but cannot strengthen scope/polarity/epistemic status;
- aggregation/redaction/generalization ≠ automatic declassification;
- alias/generalization cannot merge materially distinct subjects or change causal/Impact scope;
- `restricted`/`redacted`/`omitted` ≠ absent;
- acknowledging opaque existence is itself a disclosure decision;
- material hidden limitations must constrain the visible conclusion or cause it to be narrowed/withheld;
- Explanation cannot use otherwise hidden evidence to invent a new coarse inference;
- `inspectBasis` is requester-specific and may expose exact basis, coarse provenance/status, redaction/opaque limitation, or nothing;
- visible citation/reference ≠ permission to inspect source evidence;
- mosaic/differencing/repeated-query risk is compositional;
- cross-audience views may differ in detail/scope but cannot intentionally contradict the same visible proposition;
- communication review/release authority ≠ truth/evidence/causal/compliance/control authority;
- historical actor authorization, retained historical communication and current requester disclosure are separate;
- current authorization changes do not rewrite retained prior Explanation snapshots;
- no separate business/executive truth model or universal safe-summary level is accepted.

## Boundary with Group 07

Group 06 defines the valid visible projection at a point in time. Group 07 will refine how that projection changes when evidence, source status, authorization or materiality changes, and how retained Explanation snapshots preserve earlier communication without treating elapsed time as epistemic strengthening.

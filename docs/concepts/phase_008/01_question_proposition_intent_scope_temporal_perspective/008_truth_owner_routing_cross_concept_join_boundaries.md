# EXPL-008 — Truth-Owner Routing & Cross-Concept Join Boundaries

**Status:** Accepted — Phase 008 Group 01

## Requirement

Route each requested conclusion to the accepted concept(s) that own its substantive truth. Explanation selects and composes; it does not absorb ownership.

Examples:

- `Did it run?` → Execution History.
- `Is the result healthy/current/fresh?` → Observation/Assessment/Phase 006 semantics.
- `What changed?` → Change, with Change Intent/Deployment when intent/realization context is requested.
- `Why did it happen?` → Investigation evidence may organize inquiry, but causal assertion belongs to Causal Claim.
- `Who was affected?` → Impact encounter/exposure/effect/consequence semantics.
- `Did the safeguard prevent exposure?` → Propagation Safeguard enforcement plus Group 06/REF-028 prevention determination.
- `Did the Gate stop the run?` → Execution Gate decision/enforcement plus Execution History opportunity/start evidence; broader caused-delay statements may require Causal Claim.
- `Who owns this?` → Responsibility Assignment.
- `What does this mean?` → Semantic Definition.
- `What policy applies?` → Policy Context.
- `May I rerun it?` → Capability Authorization.

## Cross-concept joins

A question may require multiple source concepts, but temporal overlap, graph adjacency, synchronization order or co-presentation never creates a stronger proposition than the accepted join semantics permit.

Explanation must preserve the existing boundaries rather than inventing narrative joins such as `deployment happened, therefore it caused the defect` or `downstream, therefore affected`.

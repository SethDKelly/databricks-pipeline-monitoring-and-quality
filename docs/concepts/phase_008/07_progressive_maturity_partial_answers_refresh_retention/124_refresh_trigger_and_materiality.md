# EXPL-124 — Refresh Trigger & Materiality

**Status:** Accepted — Phase 008 Group 07

A refresh is semantically material when a change can alter an answer-bearing statement, required context/limitation, derivation basis, visible authorization projection, or bounded subquestion coverage.

Examples include new/corrected evidence, Assessment/Causal Claim/Impact/control/governance transitions, changed Lineage/version facts, source supersession, changed authorization, or changed materiality within the same bounded request.

Implementation-specific event triggers, schedules and notification infrastructure remain deferred.

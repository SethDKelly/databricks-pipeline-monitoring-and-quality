# Phase 005 Group 02 — Semantic, Responsibility, Classification, Policy & Criticality Governance

**Status:** Next review group — not yet started

## Goal

Apply the accepted Assertion Authority concept and AUTH-001–AUTH-008 to descriptive/governance state without conflating governance authority with normative health authority, Capability Authorization, evidence sufficiency, or production-control authority.

## Accepted handoff from Group 01

- authority is bound to category/facet/scheme/type, subject scope, context, effective time, and knowledge time where relevant;
- source assertions remain provenance-bearing regardless of standing;
- authoritative, advisory, explicitly non-authoritative, conditional, unknown, unavailable, authoritative-conflict, and authority-rule-conflict states remain distinct;
- source count, recency, availability, ingestion order, repository ownership, organizational title, responsibility, and apparent specificity do not create precedence;
- co-authoritative disagreements remain authoritative conflict unless an explicit resolver applies;
- fallback authority requires an explicit rule and evidenced activation condition;
- authority-rule provenance/governing basis is required;
- prospective authority changes and later corrections preserve historical/as-known behavior;
- Assertion Authority does not waive Phase 004 evidence burdens or grant Capability Authorization.

## Primary review questions

- Which semantic facets need independently resolvable authority?
- How should business definitions, technical descriptions, grain, units, populations, and calculation meanings use Assertion Authority?
- Which responsibility types require authoritative assignment sources and which allow shared/co-authoritative assertions?
- How should Classification authority vary by scheme/vocabulary/context?
- How should Policy Context authority vary by policy/applicability context without becoming compliance/legal interpretation?
- How is business/operational criticality established and historically revised?
- Which governance assertions may be local/context overrides versus genuine conflicts?
- How should stewardship/ownership assertions interact with, but not grant, authority?

## Boundaries

Do not define Expectation/metric threshold authority in detail (Group 03), Capability Authorization (Group 04), high-consequence control/confirmation authority (Group 05), or disclosure policy (Group 06). Do not select Collibra, Immuta, Databricks/Unity Catalog, GitHub, or human stewards as universal authorities.

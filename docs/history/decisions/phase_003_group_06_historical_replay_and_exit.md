# Decision Records — Phase 003 Group 06 Historical Replay and Exit

This file continues the durable decision sequence after D-078 in [`pre_group_06_execution_gating.md`](pre_group_06_execution_gating.md).

### D-079 — Historical replay uses event/effective time plus a knowledge cutoff

**Status:** Accepted — Phase 003 Group 06

A historically honest `as-known` view requires both the time the questioned condition/event applied and the recorded/knowledge-time cutoff limiting which evidence/assertions may contribute. Current state is never projected backward merely because it is now authoritative.

### D-080 — Historical state cuts are synchronization views, not a new concept

**Status:** Accepted — Phase 003 Group 06

The 23 accepted concepts already own their histories. SYN-033 composes those histories for replay and does not create a canonical `Historical State` truth bucket, snapshot concept, or persistence requirement.

### D-081 — Actual historical state is distinct from replay-derived interpretation

**Status:** Accepted — Phase 003 Group 06

A present-day system may compute an Assessment/Impact/Explanation over a historical evidence cut, but that replay-derived output does not prove the interpretation was actually recorded, believed, decided, or communicated at the historical time. Retained historical state and reconstructed state remain distinguishable.

### D-082 — Late/corrected evidence may revise retrospective conclusions without rewriting contemporaneous knowledge

**Status:** Accepted — Phase 003 Group 06

Late or corrected evidence can create new retrospective Assessment, Change, Causal Claim, Impact, or Explanation state with a later knowledge time. Prior conclusions remain reconstructable. Investigation closure and prior causal support do not immunize conclusions from materially new evidence.

### D-083 — Historical gate/safeguard actions are actual actions, not counterfactual replay outputs

**Status:** Accepted — Phase 003 Group 06

Later evidence may show that a past readiness/protection decision would be evaluated differently now. Historical replay preserves the actual gate hold/admit/override and safeguard proposal/activation/release that occurred. Counterfactual `what should have happened` analysis is separate from replay and is not substituted into the ledger.

### D-084 — Prospective knowledge is not backfilled from realized outcomes

**Status:** Accepted — Phase 003 Group 06

Later realized Lineage, Impact, exposure, or causal evidence cannot be inserted into an earlier Prospective Impact Profile or change-planning view as though it was known before realization. Retrospective analysis may compare the forecast/candidate set with later outcomes while preserving the original knowledge boundary.

### D-085 — Historical authorization can be reconstructed but never grants current disclosure

**Status:** Accepted — Phase 003 Group 06

A historical actor's Capability Authorization is evidence about what that actor could know/do then. SYN-035 applies the current requester's applicable authorization to present disclosure. Historical privileged access cannot be reused as a credential or leaked through paraphrase.

### D-086 — Actual retained Explanation and reconstructed historical Explanation must be distinguishable

**Status:** Accepted — Phase 003 Group 06

If an Explanation/report was actually retained at the incident knowledge time, it can be represented as historical communication. If none exists, a current `as-known-then` answer is labeled a reconstruction and cannot claim its wording/conclusion was shown to historical responders.

### D-087 — E-01–E-22 pass end-to-end Phase 003 composition

**Status:** Accepted — Phase 003 Group 06

The scenario replay matrix confirms that the 23 concepts and SYN-001–SYN-035 can express the required ecosystem behavior while preserving uncertainty, temporal truth, authorization, passive-monitoring non-interference, optional gating, safeguards, causality, layered Impact, Annotation, and Explanation boundaries.

No additional concept is required by Phase 003 consolidation.

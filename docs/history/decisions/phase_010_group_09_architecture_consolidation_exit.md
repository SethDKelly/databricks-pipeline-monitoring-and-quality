# Phase 010 Group 09 — Architecture Consolidation & Exit Decisions

## D-1663 — Group 09 is consolidation, not a new semantic design layer
**Status:** Accepted

Group 09 validates and freezes accepted architecture unless a genuine contradiction requires a new proposition.

## D-1664 — ARCH-001–ARCH-500 is the final Phase 010 architecture range
**Status:** Accepted

Whole-architecture replay found no requirement for ARCH-501.

## D-1665 — Earlier functional/evidence/governance contracts constrain architecture precedence
**Status:** Accepted

Implementation or architecture convenience cannot override SYN/REF/AUTH/HLTH/OPS/EXPL/INTG semantics.

## D-1666 — Deployment capability remains instance- and time-specific after architecture freeze
**Status:** Accepted

The Databricks-centered reference topology does not convert public capability documentation into target-environment fact.

## D-1667 — Delta-first canonical persistence remains the frozen structured evidence/governance plane
**Status:** Accepted

Managed/external realization remains deployment-bound; semantic history remains non-rewriting.

## D-1668 — Derived graph/search/vector/cache/read stores remain rebuildable and non-canonical
**Status:** Accepted

Operational importance does not create truth ownership.

## D-1669 — Serving uses current requester Capability Authorization and disclosure
**Status:** Accepted

Authentication or internal service access is not sufficient for protected projection/action.

## D-1670 — Historical truth/replay and current disclosure remain separate operations
**Status:** Accepted

Historical state is not rewritten by current permission; current requester policy still governs current visibility.

## D-1671 — Reconciliation-first hybrid acquisition remains the completeness/recovery foundation
**Status:** Accepted

Streaming/webhook/incremental paths are source-specific accelerators.

## D-1672 — Exact cross-system association requires stable identity/correlation/attestation evidence
**Status:** Accepted

Name and timestamp proximity remain invalid exact joins.

## D-1673 — Runtime implementation/input/output manifests preserve partiality
**Status:** Accepted

Missing run-specific facets are not filled from current/latest state.

## D-1674 — No universal domain or platform health score is accepted
**Status:** Accepted

Health/integration/platform/control dimensions remain proposition/service specific.

## D-1675 — Lineage reachability remains distinct from encounter/exposure/effect/consequence
**Status:** Accepted

Graph traversal cannot transitively manufacture Impact.

## D-1676 — Investigation/reasoning remains deterministic-first and evidence-bound
**Status:** Accepted

Human/model/search/graph origin may generate leads but not truth/authority.

## D-1677 — Causal confirmation remains REF-017 + AUTH-034 gated
**Status:** Accepted

Architecture consolidation does not create a shortcut for `confirmed`.

## D-1678 — Statement IR / Answer IR remains the required pre-render Explanation contract
**Status:** Accepted

Material basis/limitations/status/scope precede prose rendering.

## D-1679 — Model/search assistance remains optional and non-authoritative
**Status:** Accepted

Deterministic basic answerability must survive model/vector outage.

## D-1680 — Active control remains explicit opt-in over passive monitoring
**Status:** Accepted

A passive MVP can exit without deploying Gate/Safeguard enforcement.

## D-1681 — Execution Gate and Propagation Safeguard remain independent state machines
**Status:** Accepted

Shared infrastructure does not justify a generic `blocked/protected` semantic state.

## D-1682 — SC-06 active-control workload receives required capacity/failure-domain protection
**Status:** Accepted

Optional interactive/model workloads cannot silently determine control safety/timeliness.

## D-1683 — The MVP reference architecture is Databricks/GitHub-centered
**Status:** Accepted

It includes Delta canonical evidence, source acquisition, deterministic reasoning/replay and an authorization-aware serving boundary.

## D-1684 — Collibra and Immuta remain optional enterprise integrations
**Status:** Accepted

Their absence degrades only dependent proposition capabilities.

## D-1685 — No dedicated graph database is required for the initial MVP
**Status:** Accepted

Delta-backed derived graph projection is the default until measured needs justify specialization.

## D-1686 — No LLM is required for the initial MVP
**Status:** Accepted

Deterministic query/reasoning/rendering remains sufficient for core truth and Explanation.

## D-1687 — No universal event bus/queue is required by Phase 010
**Status:** Accepted

Introduce one only for measured distribution/burst/replay/operational needs while preserving canonical commit semantics.

## D-1688 — A thin/stateless authorization-aware service façade is the preferred serving boundary
**Status:** Accepted

UI clients do not receive unrestricted raw canonical/system-table access.

## D-1689 — Workload identity uses least privilege and prefers short-lived federation where verified
**Status:** Accepted

Long-lived shared credentials are not the default architecture.

## D-1690 — Secret values are excluded from canonical evidence and routine observability
**Status:** Accepted

Only minimum disclosure-safe references/provenance are retained.

## D-1691 — SLOs remain SC-01–SC-06 specific
**Status:** Accepted

Numeric values are deployment ADRs after measurement; SLO breach is not domain-health truth.

## D-1692 — Cost/budget policy cannot silently weaken evidence, Monitoring Scope or control safety
**Status:** Accepted

Optional enrichment may degrade first; required promises remain hard constraints.

## D-1693 — Retention is promise/value/obligation driven, not indefinite by default
**Status:** Accepted

Exact promised basis/control/communication history is pinned for its governed horizon; eligible payload may age/archive/expire explicitly.

## D-1694 — Backup/DR preserves non-rewriting history and explicit restore gaps
**Status:** Accepted

Recovery cannot make earlier missing evidence or unavailability disappear historically.

## D-1695 — GAP-009-01–GAP-009-40 all have explicit Phase 010 dispositions
**Status:** Accepted

Residual items are deployment facts, organization policy data, source/instrumentation availability or implementation choices rather than hidden semantic gaps.

## D-1696 — External consumer/business consequence telemetry remains source-specific enterprise extension
**Status:** Accepted

Absence of those integrations cannot become `not exposed/no consequence` truth.

## D-1697 — Organization-owned governance policy is required where dependent propositions require it
**Status:** Accepted

Vendor roles/access/metadata do not replace Monitoring Scope, Assertion Authority or DMTZ policy by convenience.

## D-1698 — Initial MVP does not require active-control enforcement
**Status:** Accepted

The foundation MVP remains passive monitoring/reasoning/replay focused; if control is enabled, full Group 07 semantics apply.

## D-1699 — Concrete implementation products remain in the unresolved implementation decision register
**Status:** Accepted

Framework/language/API gateway/queue/secret store/observability/cache/model/graph/IaC selections may proceed without reopening architecture only if they satisfy frozen contracts.

## D-1700 — Phase 010 Technical Architecture exits complete
**Status:** Accepted — Phase 010 closure

ARCH-001–ARCH-500 is final; ACV09-01–ACV09-120 pass; no ARCH-501 is required. The roadmap proceeds to later MVP implementation/validation planning without inventing a numbered next phase in this architecture exit.

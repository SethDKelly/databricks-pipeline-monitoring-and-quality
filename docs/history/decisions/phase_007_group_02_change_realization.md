# Decision Records — Phase 007 Group 02 Change Intent / Deployment / Realized Change

Continues after D-421.

### D-422 — Phase 007 Group 02 requires no new concept
**Status:** Accepted — Phase 007 Group 02
Change Intent, Deployment and Change remain sufficient truth owners. Intent-to-realization comparison is derived synchronization state rather than a 25th concept.

### D-423 — Preserve three independent truth owners
**Status:** Accepted
Change Intent owns planned modification/anticipated effects; Deployment owns attempts/activation/active implementation state; Change owns evidence-established realized differences. No lifecycle object absorbs all three.

### D-424 — Intent realization binds exact intent revision/component/target
**Status:** Accepted
Current/latest intent cannot be compared by convenience against historical deployment/change evidence. Multi-part intents preserve separately realizable components and target/slice context.

### D-425 — No universal deployment/version identity is accepted
**Status:** Accepted
Source revision, build/package, job/transformation definition, configuration, schema/interface and target context can be independent implementation-state facets. Repository commit is provenance, not automatic runtime identity.

### D-426 — Deployment attempt, outcome, activation and effect remain separate
**Status:** Accepted
Deployment mechanism success does not prove target activation; activation does not prove intended/downstream effect, health, execution or causality.

### D-427 — Intent↔Deployment association is evidence-backed and many-to-many
**Status:** Accepted
Association binds exact intent component, deployment, target and implementation facets with provenance. Time/name/repository proximity alone is insufficient; one deployment may realize many intents and one intent may span many deployments.

### D-428 — Realized Change is a bounded before/after transition proposition
**Status:** Accepted
Change binds exact subject/facet/context, before/after evidence, transition interval, derivation meaning and limitations. Activated implementation state can be Change while downstream effects remain separately evidenced.

### D-429 — Intent conformance is derived, not truth owned by Change Intent/Deployment/Change
**Status:** Accepted
Comparison preserves association, activation, realized-state, conformance and limitation layers. Underlying concept histories remain authoritative for their own propositions.

### D-430 — Adopt explicit intent-to-realization comparison vocabulary without a scalar score
**Status:** Accepted
For one bounded intent component/effect use `matched`, `partially matched`, `diverged`, `not realized`, `not evidenced`, `indeterminate`, `conflicting`, or `unavailable` as applicable. `Not realized` requires sufficient negative evidence. No universal percent-complete/confidence score is canonical.

### D-431 — Partial/phased realization is slice-specific
**Status:** Accepted
Environment, region, cohort/population, consumer/interface, implementation facet and rollout interval can differ. One active slice never globally realizes the intent; target count does not imply rollout percentage unless the proposition defines that measure.

### D-432 — Overlapping intents remain distinct and do not create causal attribution
**Status:** Accepted
A realized Change can be compatible with several intents/deployments. Compatibility/conformance does not prove which deployment caused an observed effect or merge overlapping intents.

### D-433 — Missing registered intent uses careful epistemic/process language
**Status:** Accepted
`No matching registered intent known`, `unregistered`, `outside declared intent scope` and `unplanned` are distinct. `Unplanned` requires an applicable planning rule plus sufficient evidence/coverage; missing registration does not imply unauthorized/improper/no human intent.

### D-434 — Undeclared anticipated effect does not prove humanly unintended behavior
**Status:** Accepted
An effect absent from a registered intent is described as not declared/anticipated in that intent unless separate evidence establishes actor intent.

### D-435 — Rollback/reversion is non-rewriting and facet-specific
**Status:** Accepted
Supersession/deactivation, rollback action, realized reversion, restoration/equivalence and roll-forward remain distinct. Reactivating a prior revision creates a new interval and does not erase the superseded interval.

### D-436 — Implementation rollback does not imply downstream restoration
**Status:** Accepted
Data already written, schema migration, topology, materializations, consumer exposure and health state require their own evidence. Same code revision does not prove the same composite operating state when configuration/facets differ.

### D-437 — Historical realization reasoning is bitemporal and non-rewriting
**Status:** Accepted
Intent registration, planned activation, deployment attempt, target activation, realized Change, framework knowledge and comparison evaluation times remain distinguishable. Late evidence can revise retrospective interpretation without rewriting what was known then.

### D-438 — Negative deployment/realization claims require REF-based coverage
**Status:** Accepted
`No deployment`, `no activation`, `no matching intent`, `not realized`, `rollback did not restore`, or `no competing deployment` require conclusion-specific opportunity/coverage. Missing telemetry/search failure is not negative truth.

### D-439 — Topology transition preserves Lineage ownership
**Status:** Accepted
Change Intent may propose topology and Deployment may activate implementation intended to create it, but OPS-001–OPS-009 Lineage evidence establishes the effective relationship. Change may describe the realized topology transition without owning/manufacturing the edge.

### D-440 — OPS-010–OPS-020 and C02-01–C02-24 are accepted; Group 02 exits complete
**Status:** Accepted
Group 02 composes without a new concept, universal version identifier, activation shortcut, scalar realization score, intent-absence overclaim, rollback rewrite, causal/health shortcut or architecture selection. The accepted OPS range is now OPS-001–OPS-020. Phase 007 Group 03 — Prospective Blast Radius & Change-Aware Review is next.

# INTG-105 — Anomaly-Detection Freshness / Completeness Model

**Status:** Accepted — Phase 009 Group 04

Databricks anomaly detection uses historical commit timing and recent row-count patterns to derive freshness and completeness anomaly results for enabled tables, with additional preview/beta detail depending on feature.

These are vendor-model Assessments against learned patterns. They do not automatically equal governed freshness SLAs, explicit completeness Expectations, event-time freshness, or current-cycle readiness.

# OPS-099 — Release Request, Effective Release & Path Reopening

**Status:** Accepted — Phase 007 Group 07

## Purpose

Refine release as an evidence-backed removal of protection at exact surfaces rather than an administrative closure label.

## Contract

Release reasoning separates:

1. release rationale/recommendation;
2. required authorization/approval;
3. release request/issuance;
4. external/control-plane acceptance where applicable;
5. effective removal of protection;
6. which paths/consumers/opportunities became available again.

Release can be partial. A safeguard may remain enforced on one cohort/path while being released on another.

## Invariants

- authorization/release request ≠ effective release.
- effective release ≠ consumer encounter.
- released path ≠ every alternate path released.
- release ≠ health, causal resolution or freshness proof.
- release history is non-rewriting.
